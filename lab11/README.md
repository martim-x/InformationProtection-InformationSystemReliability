# Лабораторная работа №11: Сжатие арифметическим методом

**Предмет:** Защита информации и надёжность информационных систем
**Тема лекции:** 07.5 «Арифметическое сжатие»
**Практикум:** ч. 1, стр. 103–111
**Программа:** `lab11/app/main.py` · **Отчёт:** `lab11/lab11.docx` (+ `lab11.pdf`)

## Задание (вариант 1)

Две части: сообщение «летоисчисление» и составное сообщение – конкатенация
строк 1–2 таблицы вариантов: «летоисчислениевремяпрепровождение». Требуется
прямое и обратное преобразования, оценка возможности переполнения, сравнение с
вероятностными методами.

## Реализовано

- `model` – таблица частот и кумулятивные границы символов на [0; 1);
- `encode` / `decode` – прямое и обратное преобразования на `fractions.Fraction` (точная арифметика);
- `bits_needed` – точное число бит без перехода к float (устойчиво к огромным знаменателям);
- `huffman_bits` – длина сообщения кодом Хаффмана для сравнения;
- режимы: `moloko`, `variant`, `overflow`, `compare`, `all`.

## Запуск

```bash
python3 lab11/app/main.py moloko    # пример методички «молоко»
python3 lab11/app/main.py variant   # обе части задания варианта 1
python3 lab11/app/main.py overflow  # рост требуемой точности
python3 lab11/app/main.py compare   # арифметический / Хаффман / ASCII
```

## Результаты

| Сообщение | Символов | Код, бит | Бит/символ | ASCII, бит |
|---|---|---|---|---|
| летоисчисление | 14 | 40 | 2,86 | 112 |
| летоисчислениевремяпрепровождение | 33 | 120 | 3,64 | 264 |

- «молоко»: итоговый отрезок [0,4381; 0,4387), ширина 5,79·10⁻⁴, 11 бит, декодирование совпало;
- переполнение: ширина падает как произведение вероятностей; 64-битная арифметика теряет точность примерно после **17 символов** (p_min = 0,0714) — нужна перенормировка;
- выигрыш к ASCII: 35,7 % и 45,5 %; с Хаффманом на этих сообщениях длины совпали (40 и 120 бит).
