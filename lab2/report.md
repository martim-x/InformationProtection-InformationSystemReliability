## 2. Теоретические сведения (кратко)

Простейшая информационная система состоит из трёх элементов: **источника сообщения (ИсС)**, **канала передачи сообщения** и **получателя сообщения (ПС)**. В системах с хранением информации в качестве канала выступает устройство хранения (например, ОЗУ), а в роли ИсС/ПС — процессор (при записи и чтении данных).

- **Алфавит, А** — общее число знаков или символов `{ai}` (1 ≤ i ≤ N), используемых для генерации или передачи сообщений; **N — мощность алфавита**. Минимальное число элементов алфавита **Nmin = 2**: `А = {0, 1}` — двоичный (бинарный) код. Один дискретный знак — элементарное сообщение, последовательность знаков — сообщение.
- Набор элементов алфавита заранее (априори, до опыта) известен ПС, однако какой именно символ выдаст ИсС в данный момент, ПС не знает. Вероятности выбора символов удовлетворяют условию Σ p(аi) = 1. Если сообщение состоит только из единиц (p(аi = 1) = 1), используют **моноалфавит** — алфавит из одного символа.
- **Вероятности p(аi)** получаются в результате анализа частотных свойств символов алфавита: **от частости (частоты) появления каждого символа в документе переходят к вероятности соответствующего события**. Объём такого документа должен быть не менее нескольких десятков килобайт.
- **Энтропия Шеннона** — информационная характеристика алфавита (источника сообщений на основе этого алфавита); термин введён К. Шенноном и Р. Хартли (2.1):

$$H_S(A) = -\sum_{i=1}^{N} P(a_i) \cdot \log_2 P(a_i)$$

> **С физической точки зрения энтропия алфавита показывает, какое количество информации приходится в среднем на один символ алфавита.**

- **Энтропия Хартли** (2.2) — частный случай энтропии Шеннона, когда все вероятности одинаковы и постоянны для всех символов алфавита:

$$H_{Ch}(A) = \log_2 N$$

- **Количество информации в сообщении** `Хk` из `k` символов (2.3), где Н(А) — энтропия алфавита с соответствующим распределением вероятностей p(аi):

$$I(X_k) = H(A) \cdot k$$

- **Энтропия бинарного алфавита** (2.4) при р(аi = 1) = р(1) и р(аi = 0) = р(0):

$$H(A_2) = -p(0)\log_2 p(0) - p(1)\log_2 p(1)$$

- **Двоичный симметричный канал (ДСК)** — канал, в котором вероятности искажения переданного 0 (событие р(1|0)) и переданной 1 (событие р(0|1)) равны, как и вероятности передачи 0 и 1. Здесь `p` — вероятность передачи бита с ошибкой, `q = 1 - p` — вероятность правильной (безошибочной) передачи. Если p > 0, переданное сообщение может содержать ошибки: **Хk ≠ Yk**. Количество информации при передаче по ДСК определяется **эффективной энтропией Hе(A) алфавита, или пропускной способностью канала** (2.5, 2.6):

$$H_e(A) = 1 - H(Y|X),\qquad H(Y|X) = -p\log_2 p - q\log_2 q$$

## 4. Методика выполнения экспериментов

1. Загружается документ, символы приводятся к нижнему регистру и фильтруются по целевому алфавиту (латиница `a–z` либо кириллица `а–я` с `ё`).
2. Частота `cnt(ai)` переводится в вероятность `p(ai) = cnt(ai) / N_док`.
3. По формулам (2.1) и (2.2) рассчитываются энтропии Шеннона и Хартли, избыточность `R = 1 - H_Ш/H_Х`.
4. ФИО кодируется в ASCII/WIN1251/UTF-8, битовая строка анализируется — энтропия бинарного алфавита (2.4).
5. Количество информации в сообщении ФИО — по (2.3) с энтропиями из шагов 3–4.
6. Для `p ∈ {0,1; 0,5; 1,0}` вычисляется `H(Y|X)` и `He`, затем `I(Y_k) = n·He`.

## 6. Выводы

1. Энтропия — количество информации, приходящееся в среднем на один символ алфавита. Для латиницы (Остин) H = 4,18, для кириллицы (Толстой) H = 4,47 бит/символ (меньше максимума Хартли из-за неравновероятности символов).
2. Избыточность языков R ≈ 0,11 — основа для алгоритмов сжатия и помехоустойчивого кодирования.
3. Бинарные 8-битные коды практически равновероятны → H(A2) ≈ 1 бит, поэтому количество информации в коде ФИО близко к длине кода в битах (223,68 и 197,92).
4. При p = 0,1 канал теряет ≈47 % информации (He = 0,531); при p = 0,5 H(Y|X) = 1 — через канал не проходит никакой информации (I = 0); при p = 1,0 ошибаются все биты детерминированно, неопределённости нет — H(Y|X) = 0 и канал снова прозрачен (инверсия битов устранима обратной инверсией).
5. С ростом помех растёт необходимость избыточного (помехоустойчивого) кодирования.
