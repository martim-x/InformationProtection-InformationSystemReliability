# Задание с листка (вариант 6) – разбор и порядок выполнения

**Дисциплина:** Защита информации в информационных системах
**Лабораторная работа:** № 5 «Избыточное кодирование данных. Итеративные коды»
**Тип задания:** индивидуальное задание на листке (не пункты 1–6 практикума)
**Проверено:** все числа ниже получены программно (`paper_check.py`), не переписаны с листка.

---

## 1. Что дано

| Величина | Значение |
|---|---|
| Информационное слово | `Xk = 101111 001010 000010 111000 100101 110011` |
| Длина `k` | 36 бит |
| Форма записи | матрица `k1 × k2 = 6 × 6` |
| `dmin` | 3 → используются **две** группы паритетов: строки (`Xh`) и столбцы (`Xv`) |
| Избыточность `r` | `6 + 6 = 12` бит, `n = 36 + 12 = 48` |
| Ошибки | 1) в бите **8**; 2) в битах **10 и 22** |

`Xhv` (паритет паритетов) в задании не используется: с ним `dmin = 4`, а на листке
зафиксировано `dmin = 3`. Это согласуется с измеренным значением из `README.md`
лабораторной (учебник обещает 4, перебор всех слов даёт 3).

## 2. Порядок выполнения

1. Разложить `Xk` в матрицу 6 × 6 **по строкам**: позиция `p` → строка
   `i = ⌈p / 6⌉`, столбец `j = ((p − 1) mod 6) + 1`.
2. Посчитать паритеты строк `Xh[i]` и паритеты столбцов `Xv[j]` (сумма по mod 2,
   чётность).
3. Записать кодовое слово `Xn = Xk ‖ Xh ‖ Xv` (48 бит).
4. Внести ошибки по номерам позиций → получить `Yn`.
5. Декодировать: пересчитать паритеты по принятым данным, сравнить с принятыми,
   получить синдром `S = Sh ‖ Sv`.
6. Одна нарушенная строка **и** один нарушенный столбец → ошибка на их
   пересечении, бит инвертируется. Любая другая картина синдрома → ошибка
   только обнаружена.

Матрица и паритеты:

```
        1 2 3 4 5 6   Xh
   1    1 0 1 1 1 1    1
   2    0 0 1 0 1 0    0
   3    0 0 0 0 1 0    1
   4    1 1 1 0 0 0    1
   5    1 0 0 1 0 1    1
   6    1 1 0 0 1 1    0
   Xv   0 0 1 0 0 1
```

`Xh = 101110`, `Xv = 001001`, кодовое слово:

```
Xn = 101111 001010 000010 111000 100101 110011 101110 001001
     └──────────── Xk, 36 бит ─────────────┘ └─ Xh ─┘ └─ Xv ─┘
```

## 3. Случай 1: ошибка в бите 8

Позиция 8 → строка 2, столбец 2. Принятое слово (данные):

```
Yn = 101111 011010 000010 111000 100101 110011
              ^ бит 8 инвертирован (0 → 1)
```

```
Sh: строка 1 – чётность сходится          0
    строка 2 – 011010, три единицы        1   <- нарушена
    строки 3–6                            0 0 0 0
Sh = 010000

Sv: столбец 2 – изменился на один бит     1   <- нарушен
    остальные столбцы                     0 0 0 0 0
Sv = 010000
```

Пересечение: строка 2, столбец 2 → позиция `(2 − 1)·6 + 2 = 8`. Бит
инвертируется обратно, `Yn′ = Xn`. Ошибка **обнаружена и исправлена** – это и
есть пометка «обнаруж. и исправл.» на листке.

## 4. Случай 2: ошибки в битах 10 и 22

Позиция 10 → строка 2, столбец 4. Позиция 22 → строка 4, столбец 4. Обе ошибки
попали **в один столбец**.

```
Yn = 101111 001110 000010 111100 100101 110011
              ^ бит 10            ^ бит 22
```

```
Sh = 010100  (нарушены строки 2 и 4)
Sv = 000000  (столбцы целы: в столбце 4 две инверсии, чётность не изменилась)
```

Синдром ненулевой → ошибка **обнаружена**. Но ни одна строка синдрома не
указывает на конкретный бит: нарушены две строки, а столбцовый синдром пуст.
Вернуть слово нельзя – исправление невозможно.

Проверка неоднозначности перебором: синдрому `010100 / 000000` соответствуют
**6** пар позиций – `(7, 19)`, `(8, 20)`, `(9, 21)`, `(10, 22)`, `(11, 23)`,
`(12, 24)`. Настоящая пара `(10, 22)` – лишь одна из шести, выбрать её нечем.

Отсюда пометка на листке «обнаруж., но не может испр.».

## 5. Почему так

- `dmin = 3` → код гарантированно исправляет **одну** ошибку и обнаруживает
  **две** (при `dmin = 3`: `t_и = (3 − 1)/2 = 1`, `t_о = (3 − 1)/2 = 1`).
- Одиночная ошибка ломает чётность ровно одной строки и ровно одного столбца –
  координаты восстанавливаются.
- Две ошибки в одной строке или в одном столбце дают чётную кратность по этому
  направлению: соответствующий синдром нулевой, координаты теряются.
- Две ошибки в разных строках **и** разных столбцах дают две нарушенные строки и
  два нарушенных столбца – тоже неоднозначно (четыре кандидата).
- Четыре ошибки в вершинах прямоугольника не обнаруживаются вовсе
  (`S = 0`) – это предельный случай, разобранный в `README.md`, раздел 5.

## 7. Что говорить на защите

- Задание – частный случай пунктов 2–5 практикума: кодирование двумя группами
  паритетов и декодирование по синдрому.
- Порядок паритетов в слове (`Xh`, затем `Xv`) фиксирован: декодер обязан
  использовать тот же.
- Синдром – это разность принятых и пересчитанных паритетов, а не «сумма
  ошибок»: ненулевой синдром говорит только о наличии ошибки.
- Первый случай – штатная работа кода, второй – демонстрация границы
  корректирующей способности при `dmin = 3`.
- Чтобы второй случай исправлялся, нужны третья группа паритетов
  (диагонали, `dmin = 4–5`) или код Хемминга с бо́льшим `dmin`.
