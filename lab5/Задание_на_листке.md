## 1. Что дано

| Величина | Значение |
|---|---|
| Информационное слово | `Xk = 101111 001010 000010 111000 100101 110011` |
| Длина `k` | 36 бит |
| Форма записи | матрица `k1 × k2 = 6 × 6` |
| `dmin` | 3 → используются **две** группы паритетов: строки (`Xh`) и столбцы (`Xv`) |
| Избыточность `r` | `6 + 6 = 12` бит, `n = 36 + 12 = 48` |
| Ошибки | 1) в бите **8**; 2) в битах **10 и 22** |

`Xhv` (паритет паритетов) в задании не используется: с ним `dmin = 4`, а на листке
зафиксировано `dmin = 3`. Это согласуется с измеренным значением из `README.md`
лабораторной (учебник обещает 4, перебор всех слов даёт 3).

## 2. Символьная схема

### 2.1 Легенда

```
→    паритет строки (Xh)                 ·   проверка сошлась  (синдром = 0)
↓    паритет столбца (Xv)                ✕   проверка не сошлась (синдром = 1)
▲    ошибочный (инвертированный) бит     ✔   строка / столбец целы
⊕    сумма по модулю 2                   ✘   строка / столбец нарушены
‖    конкатенация                        ──► перенос / переход
```

### 2.2 Как слово раскладывается в матрицу

```
Xn:  1..6     │ 7..12    │ 13..18   │ 19..24   │ 25..30   │ 31..36   │ 37..42   │ 43..48
       i=1    │   i=2    │   i=3    │   i=4    │   i=5    │   i=6    │    Xh    │    Xv
        ↓     │    ↓     │    ↓     │    ↓     │    ↓     │    ↓     │    ↓     │    ↓
```

Каждая группа из шести бит уходит в свою строку матрицы; `Xh[i]` – паритет строки `i`,
`Xv[j]` – паритет столбца `j`. При декодировании тот же порядок читается обратно.

Обратный переход (нужен при исправлении): `p = 6·(i − 1) + j`,
`i = ⌈p / 6⌉`, `j = ((p − 1) mod 6) + 1`.

### 2.3 Кодирование

```
Xk ──► [6×6] ──┬──► ⊕ по строкам  ──► Xh (6) ──┐
               │                               │
               └──► ⊕ по столбцам ──► Xv (6) ──┴──► Xn = Xk ‖ Xh ‖ Xv (48 бит)
```

### 2.4 Декодирование

```
Yn ──┬──► ⊕ по строкам  ──► Sh ──┐
     │                            │
     └──► ⊕ по столбцам ──► Sv ──┴──► S = Sh ‖ Sv ──┬── S = 0 ──► ошибок нет
                                                    └── S ≠ 0 ──► ошибка есть
```

`S` сравнивается с нулём: ненулевой синдром – ошибка есть. Дальше по картине синдрома:

```
Sh = 1 в одной строке  и  Sv = 1 в одном столбце ──► (i, j) ──► p = 6(i−1)+j ──► инверсия бита ──► Yn′
Sh = 0 или ≥ 2 единиц, либо Sv = 0 или ≥ 2 единиц ──► «обнаружено, не исправлено»
```

## 3. Порядок выполнения

1. Разложить `Xk` в матрицу 6 × 6 **по строкам**: позиция `p` → строка
   `i = ⌈p / 6⌉`, столбец `j = ((p − 1) mod 6) + 1`.
2. Посчитать паритеты строк `Xh[i]` и паритеты столбцов `Xv[j]` (сумма по mod 2).
3. Записать кодовое слово `Xn = Xk ‖ Xh ‖ Xv` (48 бит).
4. Внести ошибки по номерам позиций → получить `Yn`.
5. Декодировать: пересчитать паритеты по принятым данным, сравнить с принятыми,
   получить синдром `S = Sh ‖ Sv`.
6. Одна нарушенная строка **и** один нарушенный столбец → ошибка на пересечении,
   бит инвертируется. Любая другая картина синдрома → ошибка только обнаружена.

Исходная матрица и паритеты:

```
        j=1  j=2  j=3  j=4  j=5  j=6      Xh
  i=1    1    0    1    1    1    1     → 1
  i=2    0    0    1    0    1    0     → 0
  i=3    0    0    0    0    1    0     → 1
  i=4    1    1    1    0    0    0     → 1
  i=5    1    0    0    1    0    1     → 1
  i=6    1    1    0    0    1    1     → 0
         ↓    ↓    ↓    ↓    ↓    ↓
  Xv     0    0    1    0    0    1
```

`Xh = 101110`, `Xv = 001001`, кодовое слово:

```
Xn = 101111 001010 000010 111000 100101 110011 101110 001001
     └──────────── Xk, 36 бит ─────────────┘ └─ Xh ─┘ └─ Xv ─┘
```

## 4. Случай 1: ошибка в бите 8

Позиция 8 → строка 2, столбец 2. Принятое слово:

```
Yn = 101111 011010 000010 111000 100101 110011
              ▲ бит 8 инвертирован: 0 → 1
```

Принятая матрица с пометками (`·` / `✕` – строковый синдром `Sh`, нижняя строка – `Sv`):

```
        j=1  j=2  j=3  j=4  j=5  j=6   Sh
  i=1    1    0    1    1    1    1    ·
  i=2    0    1    1    0    1    0    ✕
              ▲   бит 8 инвертирован: 0 → 1
  i=3    0    0    0    0    1    0    ·
  i=4    1    1    1    0    0    0    ·
  i=5    1    0    0    1    0    1    ·
  i=6    1    1    0    0    1    1    ·
         ·    ✕    ·    ·    ·    ·
```

```
Sh = · ✕ · · · ·  = 010000   <- нарушена строка 2
Sv = · ✕ · · · ·  = 010000   <- нарушен столбец 2
       └──► (i=2, j=2) ──► p = 6·(2−1) + 2 = 8 ──► инверсия бита ──► Yn′ = Xn
```

Ошибка **обнаружена и исправлена** – это и есть пометка «обнаруж. и исправл.» на листке.

## 5. Случай 2: ошибки в битах 10 и 22

Позиция 10 → строка 2, столбец 4. Позиция 22 → строка 4, столбец 4.
Обе ошибки попали **в один столбец**.

```
Yn = 101111 001110 000010 111100 100101 110011
              ▲ бит 10            ▲ бит 22
```

```
        j=1  j=2  j=3  j=4  j=5  j=6   Sh
  i=1    1    0    1    1    1    1    ·
  i=2    0    0    1    1    1    0    ✕
                        ▲   бит 10 инвертирован: 0 → 1
  i=3    0    0    0    0    1    0    ·
  i=4    1    1    1    1    0    0    ✕
                        ▲   бит 22 инвертирован: 0 → 1
  i=5    1    0    0    1    0    1    ·
  i=6    1    1    0    0    1    1    ·
         ·    ·    ·    ·    ·    ·
```

```
Sh = · ✕ · ✕ · ·  = 010100   <- нарушены строки 2 и 4
Sv = · · · · · ·  = 000000   <- столбец 4 цел: две инверсии дают чётную кратность
     └─ пересечения нет: одна нарушенная строка без нарушенного столбца точку не задаёт
```

Синдром ненулевой → ошибка **обнаружена**, но исправление невозможно: тот же
синдром дают **6** пар позиций – `(7, 19)`, `(8, 20)`, `(9, 21)`, `(10, 22)`,
`(11, 23)`, `(12, 24)`. Настоящая пара `(10, 22)` – одна из шести.

Отсюда пометка на листке «обнаруж., но не может испр.».

## 6. Почему так

- `dmin = 3` → код гарантированно исправляет **одну** ошибку и обнаруживает
  **две** (`t_и = (3 − 1)/2 = 1`, `t_о = (3 − 1)/2 = 1`).
- Одиночная ошибка ломает чётность ровно одной строки и ровно одного столбца –
  координаты восстанавливаются.
- Две ошибки в одной строке или в одном столбце дают чётную кратность по этому
  направлению: соответствующий синдром нулевой, координаты теряются.
- Две ошибки в разных строках **и** разных столбцах дают две нарушенные строки и
  два нарушенных столбца – тоже неоднозначно (четыре кандидата).
- Четыре ошибки в вершинах прямоугольника не обнаруживаются вовсе
  (`S = 0`) – это предельный случай, разобранный в `README.md`, раздел 5.

## 8. Что говорить на защите

- Задание – частный случай пунктов 2–5 практикума: кодирование двумя группами
  паритетов и декодирование по синдрому.
- Порядок паритетов в слове (`Xh`, затем `Xv`) фиксирован: декодер обязан
  использовать тот же.
- Синдром – разность принятых и пересчитанных паритетов, а не «сумма ошибок»:
  ненулевой синдром говорит только о наличии ошибки.
- Первый случай – штатная работа кода, второй – граница корректирующей
  способности при `dmin = 3`.
- Чтобы второй случай исправлялся, нужны третья группа паритетов
  (диагонали, `dmin = 4–5`) или код Хемминга с бо́льшим `dmin`.
