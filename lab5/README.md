## 1. Идея итеративного кода

Итеративный код — это код произведения двух кодов простой чётности. Информационные
биты раскладываются в двумерную матрицу `k1 × k2`, а проверочные символы
(паритеты) считаются отдельно по строкам и по столбцам.

```
Xk (k бит, k = k1 · k2)  →  матрица k1 × k2
                            ↓
              + Xh (k1 бит, по строкам)
              + Xv (k2 бит, по столбцам)
              + Xhv (1 бит, общая чётность — опционально)
                            ↓
                    Xn (n = k + r бит)
```

Простота — главное достоинство: реализуется хоть на бумаге, хоть в железе.
Недостаток — сравнительно высокая избыточность.

Отличать от кода Хемминга (ЛР4) надо чётко: там проверки строятся как **столбцы
матрицы H**, здесь — как **отдельные биты по строкам и столбцам**. Формулы
разные, принцип один: избыточность нужна, чтобы поймать ошибку.

## 2. Построение паритетов

| Символ | Что это | Формула | Сколько бит |
|---|---|---|---|
| `Xh[i]` | чётность строки i | `Xk[i·k2 + j]` по всем j, mod 2 | `k1` |
| `Xv[j]` | чётность столбца j | `Xk[i·k2 + j]` по всем i, mod 2 | `k2` |
| `Xhv` | общая чётность | `p(Xk) ⊕ p(Xh) ⊕ p(Xv)` | 1 |

**Порядок записи в кодовое слово.** Практикум требует: паритеты пишутся
«сверху вниз, справа налево», то есть сначала `Xh`, потом `Xv`, потом `Xhv`:

```
Xn = Xk ‖ Xh ‖ Xv ‖ Xhv
```

Порядок можно и другой — важно, чтобы **при декодировании использовался тот же**.
В программе порядок зафиксирован и выводится явно.

**Декодирование.** Сравниваем принятые паритеты `Yh, Yv, Yhv` с пересчитанными
по принятым данным `Yh′, Yv′, Yhv′`. Синдром — разность:

```
S = (Yh ⊕ Yh′) ‖ (Yv ⊕ Yv′) ‖ (Yhv ⊕ Yhv′)
```

- `S = 0` — ошибок нет
- ненулевая строка синдрома → ошибка в этой строке матрицы
- ненулевой столбец синдрома → ошибка в этом столбце
- **пересечение** строки и столбца даёт точный ошибочный бит

## 3. Минимальное кодовое расстояние — измеренное, а не заявленное

**Лекция и практикум утверждают:** без `Xhv` → `dmin = 4`, с `Xhv` → `dmin = 5`.
**Измерено перебором всех 2^k слов: `dmin = 3` без `Xhv` и `dmin = 4` с ним.**

```
2 группы паритетов: dmin = 3  ->  исправляет 1 ошибку, обнаруживает до 1
3 группы паритетов: dmin = 4  ->  исправляет 1 ошибку, обнаруживает до 2
```

Проверено на всех допустимых разбиениях варианта 1 — результат одинаковый:

| Фигура | dmin без Xhv | dmin с Xhv |
|---|---|---|
| 4×4 | 3 | 4 |
| 4×8 | 3 | 4 |
| 2×2 | 3 | 4 |
| 2×4 | 3 | 4 |
| 3×3 | 3 | 4 |

**Почему расходится с формулой `dmin = d1 · d2 = 2 · 2 = 4`.** Эта формула верна
для произведения двух кодов простой чётности, где **на каждую строку приходится
по k2 проверочных битов** — то есть проверяется кодом `(k2; k2−1)`. В данной
конструкции на всю строку добавлен **ровно один** бит `Xh`, и на весь столбец —
**один** бит `Xv`. Поэтому одиночная ошибка в данных меняет ровно три бита
кодового слова:

- сам бит данных;
- бит `Xh` своей строки;
- бит `Xv` своего столбца.

Вес такого слова равен 3 → `dmin ≤ 3`. Слова веса 1 или 2 невозможны (ошибка
менет не менее трёх битов), значит `dmin = 3`. Добавление `Xhv` дополняет вес
до 4.

По формулам (8) и (9) лекции при **чётном** `dmin` важно не путать:

```
t_и = (d − 2)/2  при чётном d     t_о = d/2   при чётном d
t_и = (d − 1)/2  при нечётном d   t_о = (d−1)/2 при нечётном d
```

## 5. Необнаруживаемая ошибка: прямоугольник из четырёх бит

Ошибка в вершинах прямоугольника 2×2 — инвертировано ровно два бита в двух
строках и два в двух столбцах. Чётность **ни по одному направлению** не
нарушается:

```
Xn = 000000001010000100011011
Yn = 110011001010000100011011
    ^^  ^^             <- четыре ошибочных бита

Xh = 0001, Yh = 0001  -> разность = 0000
Xv = 1011, Yv = 1011  -> разность = 0000

S (без Xhv) = 00000000 = 0000 | 0000
S (с Xhv)   = 000000000 = 0000 | 0000 | 0
Yn == Xn: False
```

Все биты синдрома нулевые, все паритеты совпали, а слово передано с ошибкой.
Декодер считает слово верным, исправить **невозможно**.

**Общий бит `Xhv` здесь не помогает.** И это не совпадение, а тождество:

```
Xhv = p(Xk) ⊕ p(Xh) ⊕ p(Xv),   причём p(Xh) = p(Xv) = p(Xk)
    ⟹  Xhv ≡ p(Xk)   тождественно
```

Каждый бит `Xk` входит ровно один раз и в `Xh`, и в `Xv`, поэтому дважды
встречается в их чётностях. Проверено на 20 000 случайных словах: **0 расхождений**.
Прямоугольник содержит 4 бита, его чётность 0 → `Xhv` не меняется.

Практический вывод: **`Xhv` не даёт обнаружения, которого не дают строки и
столбцы.** Он лишь поднимает `dmin` с 3 до 4 — то есть переводит код из класса
«исправляет 1, обнаруживает 1» в класс «исправляет 1, обнаруживает 2».

## 6. Количественная оценка корректирующей способности

По заданию п. 6: генерируем N₁ слов с ошибками кратности i, считаем N₂ — кратность
определена верно, N₃ — все ошибки исправлены (`Yn′ = Xn`). Отношения N₂/N₁ и N₃/N₁
и есть оценка. По 2000 слов на кратность.

**Две группы паритетов (r = 8):**

| Кратность | N₁ | N₂ | N₂/N₁, % | N₃ | N₃/N₁, % | Обнаружено | Доля, % |
|---|---|---|---|---|---|---|---|
| 1 | 2000 | 2000 | 100.00 | 2000 | 100.00 | 2000 | 100.00 |
| 2 | 2000 | 0 | 0.00 | 0 | 0.00 | 2000 | 100.00 |
| 3 | 2000 | 0 | 0.00 | 0 | 0.00 | 1981 | 99.05 |
| 4 | 2000 | 0 | 0.00 | 0 | 0.00 | 1987 | 99.35 |

**Три группы паритетов (r = 9):**

| Кратность | N₁ | N₂ | N₂/N₁, % | N₃ | N₃/N₁, % | Обнаружено | Доля, % |
|---|---|---|---|---|---|---|---|
| 1 | 2000 | 2000 | 100.00 | 2000 | 100.00 | 2000 | 100.00 |
| 2 | 2000 | 0 | 0.00 | 0 | 0.00 | 2000 | 100.00 |
| 3 | 2000 | 0 | 0.00 | 0 | 0.00 | 2000 | 100.00 |
| 4 | 2000 | 0 | 0.00 | 0 | 0.00 | 1982 | 99.10 |

Читать надо так:

- **i = 1** — кратность и номер бита определяются всегда, слово исправляется
  полностью. `N₂/N₁ = N₃/N₁ = 100 %`.
- **i = 2 и 3** — ошибки обнаруживаются (ненулевой синдром), но определить
  кратность и все биты нельзя: одному синдрому соответствует несколько наборов
  ошибок. `N₂/N₁ = N₃/N₁ = 0`. Это и значит `t = 1`.
- **i = 4** — часть наборов не обнаруживается вовсе: это прямоугольник из
  четырёх бит. Добавить `Xhv` поднимает гарантированное обнаружение с 2 до 3:
  при i = 3 доля необнаруженных падает с **0.95 %** до **0.00 %**.

## 7. Ответы на контрольные вопросы

Вопросы 1–8 из практикума, стр. 55–56.

### 1. Основные параметры итеративного кода

| Параметр | Значение | Как определяется |
|---|---|---|
| k | длина информационного слова | `k = k1 · k2` |
| r | число избыточных символов | `r = k1 + k2` или `k1 + k2 + 1` |
| n | длина кодового слова | `n = k + r` |
| dmin | минимальное кодовое расстояние | минимальный вес ненулевого слова кода |
| Rr | относительная избыточность | `Rr = r/k` |
| R | скорость кода | `R = k/n` |
| t | число исправляемых ошибок | `(dmin − 1)/2` при нечётном, `(dmin − 2)/2` при чётном |

Для нашего варианта: `k = 16`, `r = 9`, `n = 25`, `dmin = 4`,
`Rr = 9/16 = 0.5625`, `R = 16/25 = 0.64`.

### 2. Сравнение кодов Хемминга и итеративных кодов

| Параметр | Хемминг, k=16 | Хемминг, k=8 | Итер. 2 группы | Итер. 3 группы |
|---|---|---|---|---|
| `[n;k]` | [21;16] | [12;8] | [24;16] | [25;16] |
| r | 5 | 4 | 8 | 9 |
| dmin | 3 | 3 | 3 | 4 |
| t_и | 1 | 1 | 1 | 1 |
| t_о | 1 | 1 | 1 | 2 |
| Rr = r/k | 0.3125 | 0.5000 | 0.5000 | 0.5625 |
| R = k/n | 0.7619 | 0.6667 | 0.6667 | 0.6400 |

Вывод: Хемминг при том же `k` **экономичнее** (`Rr = 0.3125` против 0.5) и даёт
лучшую скорость, но исправляет столько же ошибок (всего одну). Итеративный код
дороже, зато добавлением `Xhv` поднимает обнаружение с 1 до 2. Практически:
одиночные ошибки — Хемминг; риск двойных — итеративный с `Xhv`.

### 3. Проверочные матрицы по схеме рис. 5.1 (9 бит, без и с Xhv)

Рис. 5.1 — это двумерная схема. Для 9 бит матрица 3×3. Проверочные равенства
**не сводятся к одной матрице H** в смысле ЛР4, потому что проверки здесь
строчные и столбцовые, а не столбцовые. В матричной форме (строки проверок,
столбцы — позиции `Xn`) получается 6 проверок на 15 бит без `Xhv`:

```
H (6 × 15), Xn = [Xk | Xh | Xv], Xk = 9 бит

1 1 1 | 1 0 0 | 0 0 0     ← Xh[1]
0 0 0 | 1 1 1 | 0 1 0     ← Xh[2]
0 0 0 | 0 1 1 | 1 1 0     ← Xh[3]
1 0 0 | 0 0 0 | 1 1 1     ← Xv[1]
0 1 0 | 0 0 0 | 0 1 1     ← Xv[2]
0 0 1 | 0 0 0 | 1 0 1     ← Xv[3]
```

С `Xhv` добавляется 7-я строка — единичная на позиции `Xhv`, и ещё проверка
суммы по mod 2, что в матричной записи даёт `H (7 × 16)`.

### 4. То же по схеме рис. 5.3 (9 бит, без и с Xhv)

Рис. 5.3 добавляет к строкам и столбцам **диагональные** проверки `Xd`, считаемые
по диагоналям. Для матрицы 3×3 диагоналей три: `(0,0)(1,1)(2,2)`,
`(0,1)(1,2)`, `(1,0)(2,1)`. Каждая даёт один проверочный бит, то есть
`r = 6 + 3 = 9` без `Xhv`. Появляются три новые строки в `H`, и `dmin` поднимается
с 3 до **4** — диагонали ловят пары битов, лежащие на одной диагонали, которых
не ловят строки и столбцы.

### 5. То же по схеме рис. 5.4 (9 бит, без и с Xhv)

Рис. 5.4 — пять линейно независимых групп паритетов на 64 бита: горизонтальные,
вертикальные, две объединённые диагональные и `z`-паритеты в третьей плоскости
плюс контрольная сумма. Для 9 бит это избыточно (рис рассчитан на 64), но схема
строится так же: каждая группа — отдельный набор проверочных битов, каждая
группа даёт свою строку в `H`. Суммарно `r = 6 + 3 + 1 = 10` без `Xhv` и `11`
с ним, `dmin` поднимается до **4–5** в зависимости от того, сколько групп
задействовано.

### 6. Какое максимальное число ошибок обнаруживает итеративный код

**Формулировка ответа зависит от того, `Xhv` используется или нет.**

| Код | dmin | Максимум обнаруженных |
|---|---|---|
| без `Xhv` | 3 | 2 ошибки гарантированно |
| с `Xhv` | 4 | 3 ошибки гарантированно |

**Условие — ошибки не должны компенсироваться по направлениям.** Детектируется
любое нечётное число искажённых символов в одной строке **или** в одном
столбце. Не обнаруживаются наборы с чётным числом ошибок по каждому направлению
одновременно: простейший — прямоугольник из 4 бит (2 строки × 2 столбца).

Практический ориентир из пункта 6 работы: при 2000 случайных словах ошибки
кратности 1–3 обнаруживаются в 100 % случаев (три группы), кратности 4 — 99.10 %
(не обнаруживаются именно прямоугольники).

### 7. Какая фигура даёт наименьшую избыточность при фиксированном k

**Ответ: квадрат, `k1 = k2 = √k`.**

При `k = k1 · k2` фиксировано, избыточность `Rr = (k1 + k2 + 1)/k`. Сумма
`k1 + k2` при постоянном произведении минимальна, когда множители равны
(неравенство AM-GM). Посчитано:

| Фигура | r | Rr = r/k |
|---|---|---|
| **4×4** | **9** | **0.5625** |
| 2×8 | 11 | 0.6875 |
| 8×2 | 11 | 0.6875 |
| 1×16 | 18 | 1.1250 |
| 16×1 | 18 | 1.1250 |

**Фиксированное k — это то, при котором и сравниваем.** Дополнительно стоит
учесть форму из вопроса: для больших k выгоднее уходить в третье измерение
(куб `2×2×2` даёт `Rr = 0.875` против `1×4×4` = 0.625 при k = 16 — то есть при
равном k куб **хуже** плоского квадрата; при k = 512 плоская фигура
`8×8×8` даёт `r = 25`, `Rr = 0.0488`, а плоский `16×32` — `r = 49`, `Rr = 0.0957`,
то есть куб выигрывает). Вывод: чем больше измерений при том же k, тем меньше
избыточность, но тем сложнее реализация — минимум всегда у равносторонней фигуры.

| + диагонали + 3 проверки | 15 | 31 | 5 | 31/31 | **465/465 исправлено** | 4495 троек, **0 неразличимых** |

### Что происходит при каждой кратности

**Одна ошибка.** Хемминг: синдром совпадает ровно с одним столбцом `H`, поэтому
позиция определяется однозначно, исправление верно всегда. Итеративный код с
`dmin = 5`: то же, плюс появляется возможность различить пару ошибок.

**Две ошибки — ключевое различие.** У Хемминга обнаруживаются **все** пары
(210 из 210), но не исправляется **ни одна**: сумма двух *разных* столбцов `H`
не может быть нулём, поэтому синдром ненулевой — ошибка видна. Но синдром
указывает на **одну** позицию, а ошибок две, поэтому декодер указывает не туда.
Это **ложная коррекция**: слово после исправления становится неверным, причём
декодер считает, что исправил всё.

У кода с `dmin = 5` та же пара определяется однозначно — синдром двойной ошибки
не совпадает с синдромом ни одной одиночной. Исправлены **465 из 465**.

**Три ошибки.** У Хемминга часть троек неразличима с корректным словом: сумма
трёх столбцов `H` может дать нулевой синдром — **49 случаев из 1330 (3.68 %)**.
Обнаружить их нельзя в принципе, неразличимость встроена в определение `dmin`.

**Необнаруживаемая ошибка.** Прямоугольник из 4 бит даёт `S = 000...0`. Ни
Хемминг, ни вариант с одним `Xhv` его не ловит — тождество `Xhv ≡ p(Xk)` из
раздела 5. Ловит только добавление диагональных проверок (32 из 36
прямоугольников) и трёх дополнительных проверок (36 из 36).

### Оговорка о коде

`EXTRA_CHECKS_44` — три проверки, найденные перебором для матрицы 4×4. Для других
размеров матрицы они неприменимы: код откатывается на диагональные проверки с
частичным покрытием (`dmin = 4`). Это ограничение зафиксировано в коде.
